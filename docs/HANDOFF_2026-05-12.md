### b) The form-submit bug, root cause
- **`<button>` inside a `<form>` without `type` defaults to `type="submit"`.** This bit us hard: clicking a `SearchableSelect` trigger on the new-project wizard's Step 3 was silently creating projects.
- **Fix is permanent** in `src/components/ui/popover.tsx` — `PopoverTrigger` now forces `type="button"`. Don't regress it. If you ever add a new trigger-like button inside a `<form>`, set `type="button"` explicitly.

### c) Popovers + the Card overflow-hidden trap
- shadcn `Card` has `overflow-hidden` for rounded corners. Any popover positioned `absolute` inside a Card gets clipped.
- **Solution:** use `src/components/ui/anchored-popover.tsx` — portals the popover to `document.body` with `position: fixed`, anchored to a trigger ref. RTL-aware (`align="end"` flips), viewport-clamped, handles outside-click + Esc.
- Pattern:
  ```tsx
  const triggerRef = useRef<HTMLSpanElement | null>(null);
  // ...
  <span ref={triggerRef} className="inline-block">
    <Button onClick={() => setOpen(v => !v)}>Open</Button>
  </span>
  <AnchoredPopover
    anchorRef={triggerRef}
    open={open}
    onClose={() => setOpen(false)}
    className="z-50 w-80 ..."
  >
    <div role="dialog" aria-label="...">...</div>
  </AnchoredPopover>
  ```
- Already applied to: TaskAssigneesPanel, FollowersPanel, ProjectServicesPanel (add-package), new-project Step 2 (multi-package picker). Reuse it for any new popover that lives inside a Card.

## 6. Conventions, in one paragraph

Every mutation: zod-validate → `requirePermission(...)` → check org scope → write → `logAudit` (always) and `logAiEvent` (if business-relevant). All RPCs use `security definer set search_path = public`. RLS read via `public.has_org_access(org_id)`, write via `public.has_permission(org, '<perm_key>')`. Page-level: `requirePagePermission`. UI: Arabic RTL must work; use logical `start-*`/`end-*` instead of `left-*`/`right-*`. Empty/loading/error states required on every page. Default to no comments in code; only write a comment when WHY isn't obvious. Don't create docs or planning files unless asked.
