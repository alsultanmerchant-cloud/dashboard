## 5. Conventions you must follow

- **Migrations**: apply via `mcp__supabase__apply_migration` *and* mirror the same SQL into `supabase/migrations/NNNN_<snake_name>.sql`. Idempotent (`if not exists`, `do $$`, `or replace`). RLS read via `public.has_org_access(...)`, write via `public.has_permission(org, '<perm_key>')`. Triggers/RPCs use `security definer set search_path = public`.
- **Server actions** use `requirePermission(...)` (throws), **not** `requirePagePermission` (redirects, breaks server-action responses).
- **Type generation**: run `node scripts/regen-types.mjs` after any schema change. Never hand-edit `src/lib/supabase/types.ts`.
- **Forms with multiple inputs**: add `onKeyDown` guards so single-input Enter doesn't submit the form. The form in `/projects/new` is the reference.
- **Searchable select**: use the new `<SearchableSelect>` component (single + multi). It's already used everywhere employee + client + package selection happens.
- **Read-only Odoo**: never call `create`/`write`/`unlink` on the live Odoo. XML-RPC is for inspection only — `default_get`, `fields_get`, `read`, `search_read`. The owner has explicitly forbidden writeback.
- **Memory**: see `~/.claude/projects/-Users-mahmoudmac-Documents-projects-skylight-addons-master/memory/` for prior project context. Update when you learn new role/feedback.
