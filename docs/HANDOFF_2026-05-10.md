### e) Supabase RPC `.select(...)` quirk
- The typed Supabase client only narrows the row type when the select string is a **single literal**. Multi-line concatenation breaks it:
  ```ts
  // WRONG — collapses to GenericStringError
  .select("a, b, " + "c")
  // RIGHT
  .select("a, b, c")
  ```
  We hit this in the escalations action; it cost a typecheck loop.

### f) Indexes can't reference STABLE functions
- `create index ... on tasks(date_trunc('month', created_at))` failed with **42P17** because `date_trunc` isn't IMMUTABLE in this context. Use a plain btree on `created_at` and let range scans do the work.
